# XNote – QA Testing Project

## 📌 Project Overview

**XNote** is a note-taking application that allows users to create, edit, delete, search, and manage notes with text and image content.

This project focuses on **Quality Assurance (QA) testing** of the XNote application to verify its functionality, data persistence, permission handling, compatibility, stability, and network behavior.

The testing was performed using a combination of **functional testing, negative testing, boundary testing, persistence testing, compatibility testing, and network/API analysis**.

---

## 🎯 Testing Objectives

The main objectives of this project are:

- Verify the core functionality of XNote.
- Ensure notes can be created, edited, searched, and deleted correctly.
- Verify text and image handling.
- Verify data persistence after application close, force close, and device restart.
- Test application behavior when permissions are denied.
- Verify application behavior in different screen orientations.
- Perform basic stability and performance checks.
- Analyze network traffic related to image uploads.
- Test application behavior in offline conditions.
- Identify and document defects found during testing.

## 🐞 Defects Found

### 1. Offline Note Cannot Be Opened

**Test Case:** `TC-XNOTE-020`  
**Module:** Network

**Scenario:** Open and access an existing note while the device is offline.

**Expected Result:**
> Previously saved notes and their contents should remain accessible when the application is offline.

**Actual Result:**
> The note list can still be displayed, but the note content cannot be opened when the device is offline.

**Status:** ❌ Failed

**Potential Impact:**
Users may be unable to access previously saved note content without an internet connection.

---

### 2. Long Text Input Is Removed Without Information

**Test Case:** `TC-XNOTE-023`  
**Module:** Boundary

**Scenario:** Enter more than 5,000 characters into a note.

**Expected Result:**
> The application should handle long text without crashing and should provide appropriate handling when the maximum character limit is reached.

**Actual Result:**
> Text exceeding the limit is immediately removed, and the application does not provide information about the maximum number of characters allowed.

**Status:** ❌ Failed

**Potential Impact:**
Users may not understand why their input disappears and may lose entered content.

**Recommendation:**
Display a clear validation message or character counter when the maximum input length is reached.

## 🔍 Testing Techniques

Several testing techniques were applied in this project:

### Functional Testing

Used to verify whether the application's main features work according to the expected behavior.

Examples:

- Create note
- Edit note
- Delete note
- Search note
- Add image
- Remove image

### Negative Testing

Used to verify how the application handles invalid, empty, or restricted conditions.

Examples:

- Empty note input
- Denied camera permission
- Denied media permission
- Offline condition

### Boundary Value Testing

Used to evaluate application behavior when input approaches or exceeds a potential limit.

Example:

- Entering more than 5,000 characters.

### Compatibility Testing

Used to verify the application's usability under different screen orientations.

Example:

- Portrait
- Landscape

### Persistence Testing

Used to verify whether data remains available after different application/device states.

Tested conditions:

- Application closed
- Application reopened
- Device restarted
- Application force closed
